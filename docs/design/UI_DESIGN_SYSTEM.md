# 银发守护者 UI 设计规范

## 设计方向

银发守护者采用「安静的健康档案」作为新的视觉北极星。界面应像一份排版清楚、留白充足、可反复阅读的编辑型产品，而不是色块密集的医疗后台或营销式健康 App。

视觉关键词：极简、克制、温暖、可信、适老。玉绿色保留为品牌识别和关键操作色，但不大面积铺开；页面主要依靠暖白底、深墨文字、细分隔线、稳定字阶和明确操作建立秩序。

## 颜色令牌

| 角色 | 色值 | 用途 |
|---|---:|---|
| Primary | `#2F8F6B` | 主要操作、选中状态、健康正向状态 |
| Primary Dark | `#176B50` | 品牌文字、重要标题、深色图标 |
| Primary Light | `#EDF3EC` | 轻量选中、图标底、健康正向标签 |
| Page | `#FBFBFA` | 全局页面背景，接近纸面 |
| Surface | `#FFFFFF` | 分组容器、输入框、底部导航 |
| Text Primary | `#202622` | 标题、正文、关键数字 |
| Text Secondary | `#6F7772` | 描述、辅助信息、时间和元数据 |
| Divider | `#EAEAEA` | 1dp 分隔线和轻描边 |
| Warm Reminder | `#956400` | 用药、提醒、注意信息的文字 |
| Warm Reminder Soft | `#FBF3DB` | 小面积提醒背景 |
| Danger | `#B42318` | SOS、错误和高风险状态 |
| Danger Soft | `#FDEBEC` | 小面积风险背景 |

颜色是稀缺资源。除 Primary、Reminder、Danger 外，不新增并列主色。蓝、紫、粉只能作为已有语义资产的过渡色，后续新增组件不再使用。

颜色不能作为状态的唯一表达；必须同时提供文字、图标或可读标签。

## 排版

字体继续使用 Android 系统无衬线中文字体，保证离线稳定和长辈设备上的渲染可靠。编辑感来自字号、字重、行距、留白和文本密度，而不是下载字体。

| 层级 | 字号 | 用途 |
|---|---:|---|
| Display | `32sp` | 登录页品牌、少量情绪入口 |
| Page Title | `26sp` | 页面标题 |
| Section Title | `21sp` | 分组标题、关键卡片标题 |
| Body | `17sp` | 正文、列表主信息、表单内容 |
| Small | `14sp` | 说明、元数据、状态辅助文本 |

正文建议保持 1.5 倍以上行高。重要信息允许自然换行，不用省略号隐藏老人必须读到的内容。关键数字使用粗体，单位和状态降低一级字阶。

## 间距、形状与深度

基础间距单位为 `4dp`，常用组合为 `8 / 12 / 16 / 18 / 24dp`。页面水平边距维持 `18dp`，卡片内边距维持 `18dp`，区块间距维持 `16dp`。

形状从“圆润 App 感”收敛为“文档式容器”：

| 组件 | 圆角 |
|---|---:|
| 分组容器 / 卡片 | `12dp` |
| 主按钮 / 次按钮 | `12dp` |
| 小标签 / chip | `12dp` |
| 底部导航 | `24dp` |

普通表面不使用阴影。层级优先通过留白、1dp 分隔线、背景差异和字重表达。只有底部导航和极少数关键浮层允许 1-2dp 的轻阴影。

## 组件规范

### Buttons

主按钮高度 `56dp`，使用 Primary 背景和白色粗体文字。次按钮使用白底、Primary 描边和深绿色文字。危险按钮只用于 SOS、高风险确认和删除。

按压状态使用轻微色调变化或系统 selectable feedback，动画控制在 `150-250ms`。

### Chips / Tags

Chip 保持至少 `48dp` 可触达区域。选中态使用 Primary 背景与白字，未选中态使用白底或 Primary Light。状态标签应短、明确、可朗读，例如“正常”“已打卡”“需关注”。

### Cards / Containers

卡片是分组容器，不是装饰。所有普通卡片使用白底、`1dp #EAEAEA` 描边、`12dp` 圆角。不要做卡片套卡片；列表项优先放在一个分组容器内，用分隔线组织。

### Empty States

空状态必须包含三件事：清楚标题、解释性一句话、可执行动作。不要只显示一行“暂无数据”。图像只作为辅助，不喧宾夺主。

### Navigation

底部导航固定 5 项：AI 助手、健康档案、用药提醒、家人相册、设置。标签和流程不可改变。选中态用 Primary Light 背景、深绿图标和粗体标签表达。

### Icons

应用内图标保持统一 24dp 画布、1.8dp 描边、圆角端点。图标资源保持单色，由组件 tint 控制状态和语义。不要使用 Emoji 代替图标或状态。

## 页面模式

- 登录页：像一张清楚的入口页，品牌居中，PIN 区域安静突出，老人档案网格保持大触控。
- 首页：保留健康摘要与 AI 入口，减少多色入口竞争，快捷操作像目录行而不是彩色宣传卡。
- 健康档案：指标以“图标 + 数值 + 单位 + 状态文字”组织，AI 分析位于指标之后。
- 用药提醒：顶部直接提供“添加药品提醒”，显示今日进度、类型筛选、服药时间和打卡状态。
- 家人相册：全部照片是主入口，视觉权重大于普通相册；收藏使用文字标签，不只靠图形。
- 设置：按“家人与设备 / 安全与回忆 / 显示与辅助 / 其他”分组，组内用行和分隔线，不做独立漂浮卡堆叠。
- AI 对话：消息行使用统一 XML item，头像、气泡、时间和快捷问题保持固定底部输入结构。
- 子女模式：先给家属一个状态摘要，再呈现健康、用药、安全和联系人信息。
- 蓝牙与便民查询：主操作出现在首屏，状态使用浅色信息条，错误必须给出文字说明和恢复动作。
- 防诈与记忆：列表沿用白色分组面板、12dp 圆角和轻描边；刷新、新增等主操作保持 56dp 高度。
- 详情页：类别/媒体信息先于标题，正文放入明确表面容器，返回操作使用文字按钮。

## Do / Don't

- Do 使用大字号、强对比、明确状态文字和足够留白。
- Do 用 1dp 分隔线和白底分组组织信息。
- Do 让主要操作在首屏可见，并使用明确动词。
- Don’t 使用大面积彩色背景、渐变、厚重阴影、玻璃拟态或装饰性色块。
- Don’t 只用颜色表达健康状态。
- Don’t 用 Emoji、乱码符号或无关图标替代产品图标。
- Don’t 做卡片里再嵌套视觉卡片。
