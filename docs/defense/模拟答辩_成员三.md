## 提问 2：防诈骗推送 — OkHttp 远程拉取 + 本地兜底 + 诚实性边界

### 导师提问

防诈骗知识推送模块中，你用了 OkHttp 做远程拉取，同时也做了本地兜底。请你说明：**远程数据从哪个 URL 拉取？数据格式是什么？如果网络请求失败，本地兜底数据存在哪里？每日防诈提醒是通过什么机制实现的（WorkManager 还是 AlarmManager）？为什么选这个方案？**

### 建议展示的关键代码

| 文件 | 定位 | 作用 |
|------|------|------|
| `FraudApiClient.java` | 异步请求方法 + JSON 解析 | OkHttp enqueue()、10s 超时、URL、JSON → FraudItem 转换 |
| `FraudFragment.java` | 页面入口，约 onViewCreated/onResume | 先展示本地数据 → 远程刷新 → 失败回退本地 |
| `SafetyContentModule.java` | `getFraudTips()` 方法 | 本地兜底数据入口 |
| `Repository.java` / `FraudTipDao.java` | 本地预置数据读取 | SQLite 中的预置防诈数据 |

### 可能被追问

- OkHttp 的 enqueue() 和 execute() 有什么区别？为什么选 enqueue？
- JSON 解析用的是哪个库？org.json 还是 Gson？
- 如果 GitHub Raw 被墙或限流，除了本地兜底还有什么方案？

### 参考答辩说法

> 老师，防诈推送分为远程拉取和本地兜底两层。远程数据通过 FraudApiClient 用 OkHttp 从 GitHub Raw 拉取 JSON，请求是异步 enqueue()，设了 10 秒超时。JSON 包含 title、category、summary、detail、measures，解析后转成 FraudItem 列表。本地兜底通过 SafetyContentModule → Repository → FraudTipDao 读取预置数据，FraudFragment 进入时先展示本地数据，远程成功后替换，失败且列表为空则回退本地。
>
> 关于每日定时推送，我基于公开仓库当前代码诚实说明——FraudReminderWorker、FraudReminderScheduler、FraudNotificationHelper 三个类以及 WorkManager 依赖在公开版本中尚未找到，所以公开版本能确认的是"远程拉取 + 本地兜底"。如果本地分支已补充这些类，则每日提醒采用 WorkManager，因为防诈推送不要求精确到分钟，WorkManager 更适合这类可延迟、可恢复的周期任务，比 AlarmManager 更省电。
>
> 答辩时我会定位到 FraudApiClient.java 的异步请求和 JSON 解析逻辑，再展示 FraudFragment.java 的先本地后远程策略，最后展示 SafetyContentModule 的本地兜底读取路径。

### 加分表达

> **诚实度满分。** 主动说"公开仓库里我没有看到这三个类，build.gradle 也没有 WorkManager 依赖"——这种**基于代码事实回答、不替项目编造功能**的态度，比任何编造都加分。老师会觉得你做过了真实的代码审查和测试工作。

### 扣分风险

>
> 答辩时我会定位到 family_members 表的建表 SQL、showOneTapChooser() 的家属列表获取和弹窗逻辑、makePhoneCall() 的权限检查和拨号实现。

### 加分表达

> "无家属时不弹空列表而是 Toast 提示"——这是个好的防御性设计细节

### 扣分风险

低。如果被追问 ACTION_CALL 和 ACTION_DIAL 的区别，需能说出 ACTION_DIAL 只打开拨号盘不拨出（不需要权限），ACTION_CALL 直接拨出（需要 CALL_PHONE 权限）。

## 提问 7：天气出行建议 + 适老化界面优化

### 导师提问

你负责了天气出行建议和适老化界面优化。请说明：**天气数据从哪里获取？如何根据天气给出出行建议（比如"今天 AQI 良好，适合去公园"）？首页天气卡片上推荐的"附近地点"是怎么从 POI 搜索转为结构化推荐的？**

**适老化方面，三级字体（标准 1.0x / 加大 1.2x / 特大 1.4x）的缩放逻辑是怎么实现的？切换字体后需要 `requireActivity().recreate()` 重建 Activity，那当前页面的状态（比如 AI 对话历史、健康数据录入到一半的表单）会丢失吗？高对比度模式具体改了什么颜色？**

### 建议展示的关键代码

| 文件 | 定位 | 作用 |
|------|------|------|
| `WeatherModule.java` | `load()` + `buildReport()` | 天气获取 + WeatherAdviceEngine 评估 + WeatherReport 生成 |
| `WeatherClient.java` | 天气 API 请求 | 网络请求获取天气和 AQI 数据 |
| `WeatherReport.java` | summary / advice / suitableForOuting / notificationSummary 字段 | 天气报告数据模型 |
| `HomeFragment.java` | 天气卡片绑定 + 一键导航按钮 | 首页天气展示 |
| `SettingsFragment.java` | 字体/对比度设置开关 | 适老化开关入口 |
| `BaseActivity.java` / `FontScaleHelper.java` | `attachBaseContext()` + `withAppFontScale()` | 字体缩放应用到 Configuration.fontScale |
| `res/values/themes.xml` | 主题定义 | 高对比度 MODE_NIGHT_YES 配置 |

### 回答要点

- 天气链路：高德定位拿经纬度（失败则广州默认）→ WeatherClient.load() 获取天气和 AQI → WeatherAdviceEngine.evaluate() 判断是否适合外出 → buildReport() 生成 WeatherReport
- 适合外出 → 搜索"公园、广场、社区活动中心"；不适合 → 搜索"医院"；POI 半径 5000m，按距离排序
- 推荐文案拼接："推荐：某公园，距您 800m；如需就医，某医院距您 1.2km"
- 诚实说明：WeatherNavigationPlace.java 在公开版本未看到，如有结构化地点模型是在本地分支
- 三级字体存在 SharedPreferences 的 elder_settings/font_mode：normal=1.0x、large=1.2x、xlarge=1.4x
- FontScaleHelper.withAppFontScale() 在 BaseActivity.attachBaseContext() 中应用到 Configuration.fontScale
- recreate() 重建 Activity：持久化数据（数据库中的聊天历史、健康数据）可恢复；临时 UI 状态（未保存的表单输入、未发送的消息）会丢失
- 高对比度通过 MODE_NIGHT_YES 切换夜间模式实现，不是逐个控件改色

### 可能被追问

- MODE_NIGHT_YES 切换夜间模式，你们有没有自定义夜间主题的颜色？还是用的系统默认？
- FontScaleHelper 的 textPrimary / textSecondary / bgPage 这些颜色入口实际用到了吗？
- WeatherAdviceEngine 的判断规则是什么？AQI 多少算"不适合外出"？

### 参考答辩说法

> 老师，天气模块的流程是：先高德定位拿经纬度，定位失败则用默认广州坐标。WeatherClient.load() 获取天气和 AQI，WeatherAdviceEngine.evaluate() 判断是否适合外出，buildReport() 生成 WeatherReport 包含 summary、advice、suitableForOuting。适合外出时搜索附近公园广场，不适合时搜索医院，POI 半径 5000 米按距离排序，拼成"推荐：某公园，距您 800m；如需就医，某医院距您 1.2km"的推荐文案。
>
> 适老化方面，三级字体缩放系数（标准 1.0x、加大 1.2x、特大 1.4x）存在 SharedPreferences 的 elder_settings/font_mode 中。FontScaleHelper.withAppFontScale() 在 BaseActivity.attachBaseContext() 时把系数应用到 Configuration.fontScale，所以页面重建后字号统一变化。
>
> 切换字体后调用 recreate() 重建 Activity，这是为了让新字号立即生效。重建时已持久化的数据（如 AI 聊天历史保存在数据库、健康数据已写入 SQLite）不会丢——重新加载即可；但临时 UI 状态（如正在输入但未保存的表单、输入框里还没发送的文字）会丢失，后续可通过 onSaveInstanceState() 或 ViewModel 优化。
>
> 高对比度开关存在 SharedPreferences 的 theme_high_contrast，开启后通过 MODE_NIGHT_YES 切换夜间模式，大幅提高文字和背景的对比度。
>
> 答辩时我会定位到 WeatherModule 的 load() 和 buildReport() 方法，再展示 BaseActivity.attachBaseContext() 中 FontScaleHelper 的应用逻辑，以及 SettingsFragment 的字体和对比度切换。

### 加分表达
