# 首页天气卡片一键导航 — 更新文档

> 更新日期：2026-06-21  
> 项目：银发守护者（Silver Guardian）  
> 模块：HomeFragment / WeatherModule / CommunityPoiSearchModule

---

## 一、更新概述

本次更新对首页“天气出行建议”卡片进行了适老化交互增强，在保留原有天气摘要、出行建议文字和 `CommunityActivity` 兜底跳转的前提下，新增了可直接执行的“一键导航”能力。

本次改造的核心目标是：

1. 把天气模块里已有的 POI 搜索结果从“只拼进 advice 文本”升级为“结构化推荐地点”。
2. 在首页天气卡片中新增默认隐藏的“一键导航”按钮。
3. 老人点击后先选地点，再直接调起高德地图步行导航，减少二次搜索和重复点击。
4. 高德未安装、POI 缺失、天气或网络失败时提供友好兜底，不让首页崩溃。

### 改造前

```text
WeatherModule
  └── 搜索休闲地点 / 医院
        └── 仅把地点名和距离拼进 advice 文本

HomeFragment
  └── 点击天气卡
        └── 根据 suitableForOuting 传“公园”或“医院”
              └── 跳转 CommunityActivity
                    └── 用户再次选择地点
                          └── 再点击导航
```

### 改造后

```text
WeatherModule
  └── 搜索休闲地点 / 医院
        ├── 继续生成 advice 文本
        └── 额外生成 recommendedPlaces 结构化列表

HomeFragment
  ├── 天气卡仍可点击进入 CommunityActivity（兜底）
  └── recommendedPlaces 非空时显示“一键导航”
        └── 弹出“选择导航地点”
              └── 选择某个地点
                    ├── 优先调起高德地图
                    └── 失败时询问是否使用网页版步行导航
```

## 四、数据模型变更

### 4.1 WeatherReport

本次为 `WeatherReport` 新增：

```java
public final List<WeatherNavigationPlace> recommendedPlaces;
```

设计要求：

- 保留原有 `summary / advice / notificationSummary / suitableForOuting`
- `recommendedPlaces` 不能为空
- 传入 `null` 时自动转为 `Collections.emptyList()`
- 首页直接读取时不会出现 `NullPointerException`

### 4.2 WeatherNavigationPlace

新增轻量模型：

```java
public final String name;
public final double lat;
public final double lon;
public final String type;
public final String distanceText;
public final PoiItem poiItem;
```

字段含义：

- `name`：地点名称
- `lat / lon`：经纬度
- `type`：地点类型，当前为 `leisure` 或 `hospital`
- `distanceText`：距离文本，如 `300m`、`1.2km`
- `poiItem`：原始高德 `PoiItem`，用于直接复用现有导航方法

## 五、推荐地点生成逻辑

### 5.1 核心规则

`WeatherModule.buildReport()` 在生成原有天气建议文字的同时，额外构建 `recommendedPlaces`：

1. 如果天气适合出门：
   - 把 `leisure` 列表中的 POI 转成推荐地点
   - `type = "leisure"`
2. 无论天气是否适合出门：
   - 如果最近医院存在，则追加一个医院推荐
   - `type = "hospital"`
3. 如果天气不适合出门：
   - 不推荐休闲地点
   - 只保留医院作为应急导航兜底
4. 如果没有任何 POI：
   - `recommendedPlaces` 为空列表
   - 首页按钮自动隐藏

### 5.2 与原文案的关系

本次没有破坏原有天气卡片上的文字展示逻辑：

- `summary` 仍显示“城市/区县 + 天气 + 温度 + AQI”
- `advice` 仍按原规则显示“适合出门 / 建议在家活动 / 就医兜底”
- 只是新增了结构化 POI，供首页按钮直接使用

### 5.3 异常兜底

`unavailableReport()` 也同步适配了新构造函数：

- 天气或空气质量不可用时，仍返回安全提示文案
- `recommendedPlaces` 使用空列表
- 首页不会显示空按钮，也不会因为空引用崩溃

## 六、首页交互更新

### 6.1 天气卡片按钮显示逻辑

在 `view_weather_card.xml` 中新增：

- id：`@+id/home_weather_nav_btn`
- 文案：`一键导航`
- 高度：`48dp`
- 样式：沿用 `@drawable/bg_button_primary`
- 默认：`visibility="gone"`

在 `HomeFragment.bindWeather()` 中：

- 加载中：
  - `summary` 显示“正在定位并获取天气…”
  - `advice` 显示“将综合天气、温度和空气质量生成出行建议。”
  - `navBtn` 强制隐藏
- 加载成功：
  - 正常更新 `summary` 与 `advice`
  - 若 `recommendedPlaces` 非空，则显示按钮
  - 若为空，则按钮保持隐藏

### 6.2 天气卡片本身的兜底行为

原有卡片点击逻辑继续保留：

- `suitableForOuting = true` 时，跳转 `CommunityActivity` 并传入 `initial_keyword = "公园"`
- `suitableForOuting = false` 时，跳转 `CommunityActivity` 并传入 `initial_keyword = "医院"`

这样即使推荐地点为空，老人仍然可以通过天气卡进入便民查询页面。

## 七、导航交互设计

### 7.1 选择地点弹窗

新增 `showWeatherNavigationDialog(List<WeatherNavigationPlace> places)`：

- 如果列表为空：
  - Toast：`暂无可导航地点`
- 如果列表非空：
  - 弹出 `AlertDialog`
  - 标题：`选择导航地点`
  - 列表项格式：

```text
越秀公园 · 距您 800m
广东省人民医院 · 距您 1.2km
```

### 7.2 发起导航

新增 `startWeatherNavigation(WeatherNavigationPlace place)`：

1. 优先调用：

```java
communitySearch().openNavigation(requireContext(), place.poiItem)
```

2. 如果返回 `false`：
   - 弹窗标题：`未安装高德地图`
   - 弹窗内容：`是否使用网页版步行导航？`
   - 点击确定后调用：

```java
communitySearch().openWebNavigation(requireContext(), place.poiItem)
```

3. 如果 `place` 或 `poiItem` 不可用：
   - Toast：`导航地点暂不可用`

### 7.3 复用现有能力

本次没有重新实现地图 URI，也没有修改 `CommunityPoiSearchModule` 的公开接口：

- 继续复用 `openNavigation(Context, PoiItem)`
- 继续复用 `openWebNavigation(Context, PoiItem)`

这样可以保证导航行为与便民查询页保持一致。

## 八、适老化体验说明

本次更新重点遵循了项目现有设计规范中的适老化要求：

1. 主按钮文案使用“**一键导航**”，避免技术术语。
2. 按钮使用高对比主色背景和白色粗体字，便于识别。
3. 弹窗标题明确写为“**选择导航地点**”。
4. 列表项同时显示“地点名称 + 距离”，方便老人快速判断。
5. 无 POI 时不弹空白弹窗，直接隐藏按钮或显示友好提示。
6. 高德未安装时明确说明可改用网页版导航，不出现英文错误。
