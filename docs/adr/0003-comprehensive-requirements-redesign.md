# 课程新需求全面改造决策

## Status

Accepted

## Context

原原型 App 存在大量硬编码数据（用户姓名、健康指标值、用药方案、UI 字符串等），且颜爷爷和林奶奶两个预设用户共用同一套数据。课程评审要求实现完整的多用户隔离、数据动态化、以及多项新增功能（一键呼叫、SOS、导航、通知栏语音播报、适老化增强等）。

经过逐条需求讨论与方案确认，形成以下 12 项需求的完整决策。

## Decisions

### 需求 1：多用户数据隔离（替代原"需求 10：做到"）

**每个用户登录后，看到的是完全属于他自己的那份数据。**

- 所有带 `user_id` 的表，seed 和读写以当前登录用户为基准，不再默认查 user_id=1
- MedicineLibrary、FraudTips 从 Repository static 共享改为人各一份。新建用户时从默认模板（8 种常见药品 + 4 条防骗贴士）拷贝初始数据
- 所有写死"颜爷爷"的 UI 字符串改为从当前用户的 name 字段动态取值
- 创建新用户时自动为该用户跑一遍所有 seed，拿到初始空白数据 + 默认模板
- 颜爷爷和林奶奶的旧数据全部清空，与新建用户一样走默认模板重新初始化
- 不改 UI 布局和交互行为，只改数据层和字符串取值方式

### 需求 2：健康档案硬编码动态化

- 4 个概览卡片（血压、心率、血氧、睡眠）改为从 SQLite 读取当天最新记录，不再写死值
- 外部实时数据优先（蓝牙设备回调 + AI 对话解析），落库后从库读取
- 概览卡片固定 4 个核心指标，下方加"更多记录"列表使用现有 `item_health_card.xml`
- "今日"严格按当天过滤
- 顶部横幅：用户名从 User.name 动态取值 + 状态用简单规则判断（全正常→"状态平稳"，有异常→"部分指标异常"）

### 需求 3：用药提醒与 AI 对话双向同步

- AI 推荐药物时输出结构化 JSON `{"drugs":[...]}`，App 解析后弹窗确认是否加入用药列表
- 双重兜底：prompt engineering 要求 JSON 格式 + App 端正则/关键词提取药名
- 用户当前用药列表和服药打卡状态作为 AI 对话上下文发送
- MedicineLibrary 作为初始模板，AI 推荐的新药反向扩充药库
- 现有 `system_prompt.txt` 中的药品推荐表动态由 MedicineLibrary 生成

### 需求 4：家人相册上传与删除

- 上传流程重写：先选图/拍照 → 填标题和留言 → 一次性入库（修复 URL 未持久化 Bug）
- 添加 CAMERA 权限，支持现场拍照和从系统相册选取
- 添加单张照片删除功能，保留现有整相册删除
- 图片双存：App 私有目录 + 外部 Pictures 文件夹

### 需求 5：登录 PIN 提示

- PIN 输入框添加显示/隐藏切换（小眼睛图标）
- 新建用户时可选填提示问题 + 提示答案
- 登录页"忘记 PIN"→ 显示提示问题 → 用户输入答案 → 验证通过后显示 PIN
- 验证逻辑：用户输入答案与创建时填写的答案匹配

### 需求 6：药品库功能完善

- 药品库从内存静态列表改为 SQLite 持久化存储
- 新增独立的"浏览药品库"页面（可按疾病分类浏览）
- 完整 CRUD 权限模型：老人可浏览和搜索，家属模式（ChildMode）可新增/编辑/删除
- AI 推荐的药品自动入库（去重处理）

### 需求 7：健康档案手动记录

- 支持全部 13 种健康指标的手动输入
- 智能弹窗 UI：根据指标类型动态调整输入控件
  - 血压：收缩压 + 舒张压双输入框
  - 心率/步数/体温/体重等：单数值 + 单位选择
  - 心情：表情符号选择器
  - 睡眠：小时 + 分钟
- 记录插入后同步刷新概览卡片

### 需求 8：便民查询导航功能

- 点击地图 POI 标记 → 在地图上绘制步行路线（替换现有纯文本弹窗）
- POI 信息栏显示于类别筛选按钮下方：距离 + 步行时间
- "开始导航"按钮：检测高德 App 安装 → 有则跳转高德 App 导航，无则弹窗提供网页版导航选项
- 保留现有 5 类 POI 搜索（菜市场、医院、药店、超市、银行）

### 需求 9：一键呼叫与 SOS 紧急呼叫

**一键呼叫：**
- 首页绿色按钮，点击弹出大按钮快捷选择（仅家属，不含 120）
- 选中后直接拨出电话（ACTION_CALL + CALL_PHONE 权限）

**SOS 紧急呼叫：**
- 首页红色按钮（复用现有 `bg_button_sos.xml` 和 `sos_button` 字符串资源）
- 点击弹出确认对话框"是否紧急呼叫？"
- 10 秒未做任何操作，自动拨打 120（课设展示使用空号/测试号）
- 用户确认后弹出联系人列表（120 测试号 + 家属列表）
- 支持逐个拨打直到有人接听（或列表耗尽）

两个按钮相互独立，并排在首页。

### 需求 10：用药提醒通知栏 + 语音播报

- 修复核心 Bug：加药时立即设置 AlarmManager 闹钟（目前仅在 BootReceiver 开机时设置）
- 删药时取消对应 PendingIntent
- 添加 `SCHEDULE_EXACT_ALARM` 权限（Android 12+ 精确闹钟）
- 用户可自定义提醒时间、提前提醒分钟数
- 错过未点"已吃"→ 可配置的重复提醒（次数 + 间隔）
- 保留现有 `ReminderBroadcastReceiver` 通知栏推送 + `TtsHelper` 语音播报机制

### 需求 11：长辈模式（字体联动首页极简布局）

- 替换原"A 方案"：不再新增独立"长辈模式"开关，直接替换现有字体大小设置的行为
- 设置页字体 Spinner 三级联动首页布局：

| 字体档位 | 字号缩放 | 首页布局 |
|----------|---------|---------|
| 标准 | 1.0x | 完整布局（欢迎横幅 + 健康概览 + 快捷方式 + AI 卡片） |
| 加大 | 1.2x | 精简（大按钮快捷网格 + 今日用药提醒卡片） |
| 特大 | 1.4x | 极简（仅 SOS + 一键呼叫 + 用药提醒 + AI 对话，4 个大按钮） |

- `FontScaleHelper` 新增 `isSimplifiedMode()` 方法
- `HomeFragment` 根据模式加载不同布局文件

### 需求 12：额外老人功能

**AI 语音对话增强：**
- 对话页默认语音输入（长按说话）
- AI 回复自动 TTS 语音播报
- 基于现有 `TtsHelper` 和语音识别代码扩展

**每日关怀通知：**
- 每天早 8 点推送关怀通知（当日天气 + 今日服药计划汇总）
- 复用 `ReminderBroadcastReceiver` 架构，新增提醒类型

**子女端增强：**
- 一键回拨老人（从 ChildModeActivity 直接拨打老人关联的家属号码）
- 远程帮老人添加用药提醒（ChildMode 内操作写入老人数据）
- 远程查看老人实时位置（通过位置权限 + 高德 SDK）

**天气卡片 + 出行建议：**
- 高德 SDK 定位获取城市名 → 和风天气 API 获取当地天气（类型+温度+AQI）
- 三项综合规则判断是否适合出门（天气类型 / 极端温度 / AQI>150）
- 适合出门时 POI 推荐附近公园（降级搜广场 → 社区活动中心），同时附最近医院
- 首页卡片 + 早 8 点每日关怀推送联动

## Consequences

- 数据层重构：所有 DAO seed 方法需接收 userId 参数，Repository 结构从 static 共享改为 per-user
- 新增 SQLite 表：`medicine_library`（药品库持久化）
- 新增权限：`CAMERA`、`SCHEDULE_EXACT_ALARM`
- 新增布局文件：`fragment_home_simplified.xml`（精简首页）、`fragment_home_minimal.xml`（极简首页）、药品库浏览页、天气卡片
- UI 字符串资源全面去硬编码，"颜爷爷"相关字符串改为动态取值或移除
- `EmergencyDao.readAll()` 硬编码 Bug 修复（time 和 status 字段从实际 DB 值读取）
- 120 号码在课设版本中使用测试空号
- 评分覆盖：SQLite 多表关联 ✓、AlarmManager 精确闹钟 ✓、TTS 语音播报 ✓、Camera 权限 ✓、高德步行路线绘制 ✓、SharedPreferences 联动 ✓
